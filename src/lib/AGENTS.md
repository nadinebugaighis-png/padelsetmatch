- Any player may edit a visible match's where/when/level/note (match-player-edit.ts); cancel/delete/gender/booking/class stay host-only.
- Game length is match_events.duration_minutes (60 or 90, default 90); read it through matchDuration/matchEndsAt in match-rules.ts and never hardcode "90 min", so feeds, detail and share pages agree.
- Passing hosting (transfer_match_host) changes match_events.host_profile_id, deletes the new host's participant row and re-inserts the old host as a participant (ON CONFLICT DO NOTHING); keep that in mind because participant row changes can fire leave/join alerts and drop a host from the line-up.
- Play card button comes from matchCardAction (match-rules.ts): Manage for players in the game, Join/View for others; the card itself still opens any game so every player can edit. Signup age range and languages are optional (blank range saves as all ages via resolveAgePreference) so new players reach the app faster.
- Ready-made daily games (auto_slot_id) start neutral: houseGameUnclaimed (match-rules.ts) hides the host until the host is playing; DB triggers make the first joiner host and pass hosting to the next player (or back to the slot organiser) when the host leaves. Their hosts cannot cancel/delete them (admins only), so one player cannot remove a shared game.
- Games with no hour yet use match_events.time_tbd (copied from open_game_slots.time_tbd) with a placeholder late-evening starts_at so they stay listed all day; screens and alerts show "Time"/date only when time_tbd, and the edit form clears it once a player picks an hour (startFromFormValue in match-rules.ts).
- Native iOS Apple sign-in (native.ts) gets id_tokens whose audience is the app bundle ID, while the Apple provider holds only the web Services ID (the sign-in broker breaks on a comma list); apple-native.functions.ts verifies the token against Apple's keys (issuer, audience, nonce, verified email) and returns a one-time magic-link hash the app redeems with verifyOtp. Ordinary sign-out uses scope local so leaving on one device never ends sessions on others.
- Competitions (Americanas, pozos, leagues) live in competitions/competition_entries; any signed-in player can announce one (RLS creator = my_profile_id()), only admins may set hosted (guard trigger), and the capacity trigger rejects entries unless hosted, so in-app sign-up exists only for PadelSetMatch events; posters go to the private competition-posters bucket and competitions store only poster_path (a trigger requires the uploader's own folder); competitions.functions.ts hands out one-hour signed links through the viewer's RLS and deleteCompetition removes the file with the row, so a deleted poster stops opening.
- Coach lessons live in coach_slots (coach-lessons.functions.ts): coaches insert open times directly under RLS, but request/accept/decline/cancel only run through SECURITY DEFINER RPCs that also enqueue alerts, so status changes and notifications can't drift apart. Alert bodies omit times because recipients span time zones. Each time carries lesson_place (club, travel = coach comes to the player, both = player picks) and request_coach_slot resolves the player's place and requires their address note for home lessons; placeFields/requestPlace in coach-lessons.ts mirror these rules. Accepting a lesson opens an already-accepted chat (ensure_lesson_thread, origin coach_lesson) and open_lesson_chat reopens it for the coach or player only; booked lesson pairs skip the one-intro-message limit, so coach approval stays the only gate. Each time can also take an open group (offers_group, group_price_note); players book through book_coach_slot with lesson_kind private/group (request_coach_slot stays for older app versions). Accepting a group creates a coach-hosted is_class match_event (4 students, first player in) linked by coach_slots.match_event_id, so joining, chat, sharing and the Matches feed reuse match code; coach cancel cancels that match, a player cancel just leaves it.
- The Play feed aggregates by the player's own areas via feed-areas.ts (server keywords and client area chips share it); an area never widens to its whole city, a city with no area covers the city, and no areas means every game, so a La Moraleja player never sees Salamanca games.
- Matches shared from Playtomic (match_events.joins_on_playtomic + playtomic_link) are joined only on Playtomic: playtomicJoinLink/playtomicListingExpired in match-rules.ts drive the UI, a trigger blocks in-app and guest joins except the host, only the host edits, and listings expire at start time, because we never fetch Playtomic data or claim live availability.
- "Who can play?" on Connect shows one area at a time (home area first, then the main preset communities via connectAreaOptions in who-can-play.ts); browsing never changes the profile or alerts. Each check-in (play_checkins, one per player per day+slot) is tagged with the single chosen area key, and each area+day+slot has its own chat (play_slot_messages: readable by unblocked adults, writable only by players checked in to that exact slot, alerts other checked-in players at most every 10 minutes). Blocked pairs are skipped everywhere and the community board stays worldwide.
- "Add to calendar" serves a stateless .ics from /api/public/calendar/$eventId built by match-calendar.ts from public_match_view only (no sign-in, since phone calendars fetch it directly), so it never reveals more than the shared match page; timed, open/full, non-Playtomic games only. The app opens it (and Google/Outlook prefilled links) from a picker sheet using the live site address, because previews are sign-in walled and calendar files cannot open inside a frame.
- Communities are derived from profiles.locations, not a table: communities.ts folds each saved place into a community (canonical area, or whole city for city-wide places) and counts members with the same rule as the grid gate in area-match.ts, so the directory, Home and Play always agree. Joining/starting/leaving only edits the player's own locations (communities.functions.ts); "viewing" a community (one of mine or a visit) is a device-local choice (community-view.ts) passed to getDiscoverFeed/listOpenEvents as `visit`, so browsing never changes the profile. Communities with their own seal are listed in branded-communities.ts (always shown, logo via .asset.json), and press-and-hold on a row opens a share sheet (the Share tap must be a real tap; phones block share/clipboard from timers) for /app/communities?c=<location>, which shows that community first with Join. Cities whose only community is the whole city (isCityOnly) are listed once, grouped per country, never as a city heading repeating the same name. Visiting a community you don't belong to (isVisitingOther) lists every member without the viewer's age filter and hides the viewer's own card, so the grid matches the directory count; a near-empty community shows a 'just starting' note with Share instead of a filters hint.
- The public Communities list goes through publicDirectory (communities.ts): one-member communities are hidden unless mine or branded, and only my home country shows until "See the whole world", so the list never looks empty while founders can still share theirs. Push permission is asked once after joining/creating a match (ask-push.ts), never by a permanent banner.
