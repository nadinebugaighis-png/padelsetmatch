- Any player may edit a visible match's where/when/level/note (match-player-edit.ts); cancel/delete/gender/booking/class stay host-only.
- Game length is match_events.duration_minutes (60 or 90, default 90); read it through matchDuration/matchEndsAt in match-rules.ts and never hardcode "90 min", so feeds, detail and share pages agree.
- Passing hosting (transfer_match_host) changes match_events.host_profile_id, deletes the new host's participant row and re-inserts the old host as a participant (ON CONFLICT DO NOTHING); keep that in mind because participant row changes can fire leave/join alerts and drop a host from the line-up.
- Play card button comes from matchCardAction (match-rules.ts): Manage for players in the game, Join/View for others; the card itself still opens any game so every player can edit. Signup age range and languages are optional (blank range saves as all ages via resolveAgePreference) so new players reach the app faster.
- Ready-made daily games (auto_slot_id) start neutral: houseGameUnclaimed (match-rules.ts) hides the host until the host is playing; DB triggers make the first joiner host and pass hosting to the next player (or back to the slot organiser) when the host leaves. Their hosts cannot cancel/delete them (admins only), so one player cannot remove a shared game.
- Games with no hour yet use match_events.time_tbd (copied from open_game_slots.time_tbd) with a placeholder late-evening starts_at so they stay listed all day; screens and alerts show "Time"/date only when time_tbd, and the edit form clears it once a player picks an hour (startFromFormValue in match-rules.ts).
- Native iOS Apple sign-in (native.ts) sends id_tokens whose audience is the app bundle ID, so the Apple provider must run on owner credentials listing both the web Services ID and the bundle ID; managed Apple credentials reject it.
